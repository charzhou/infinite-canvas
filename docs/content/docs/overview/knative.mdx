# Knative 部署

主镜像 `ghcr.io/charzhou/infinite-canvas:v0.10.3` 同时包含 Vite 前端和同源 OIDC BFF。部署一个 Knative Service 即可，浏览器请求会经同一 HTTPS Origin 访问 `/api/oidc/*`。

## 创建 OIDC Secret

将 `deploy/knative/oidc-secret.example.yaml` 复制到仓库外的私有位置，填入客户端 ID、客户端密钥、会话密钥和实际公网域名后创建 Secret：

```bash
kubectl -n default apply -f /private/path/infinite-canvas-oidc.yaml
```

`OIDC_SESSION_KEY` 必须是 base64url 编码的 32 字节随机值，可用以下命令生成：

```bash
openssl rand -base64 32 | tr '+/' '-_' | tr -d '=\\n'
```

`OIDC_ISSUER` 仍然是规范 Issuer，例如 `https://ai.nekotech.us`。`OIDC_GATEWAY_BASE_URL` 是可选项，默认与 Issuer 相同；如果希望算力请求走 CDN 加速域名，可以填 `https://sub2api.tegical.com`。如果在其前面挂 CDN 或反向代理，它必须透传 `Authorization: Bearer`、streaming 响应、`Range` 和二进制媒体内容，默认不要缓存已认证 API 响应。`PUBLIC_ORIGIN` 必须是 Knative 对外暴露的 HTTPS Origin，例如 `https://canvas.example.com`。在 OIDC Provider 中注册精确回调地址：

```text
https://canvas.example.com/api/oidc/callback
```

## 部署 Service

```bash
kubectl -n default apply -f deploy/knative/service.yaml
kubectl -n default get ksvc infinite-canvas -w
```

清单将 BFF 上游请求和 Knative 单请求超时均设为 10 分钟。若集群的 Knative 最大请求超时低于 600 秒，需要由集群管理员调整 Serving 配置或降低该值。

## 验证

Service Ready 后，使用其外部 URL 验证 BFF 配置：

```bash
URL=$(kubectl -n default get ksvc infinite-canvas -o jsonpath='{.status.url}')
curl -fsS "$URL/api/oidc/config"
```

结果应包含 `"enabled":true` 和 `"providerName":"Sub2API"`。若镜像仓库为私有仓库，还需创建 `imagePullSecret` 并在 Service 中引用它。
