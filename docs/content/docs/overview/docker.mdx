# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## OIDC compute channel

The OIDC channel is provided by the same-origin BFF and is unavailable on purely static deployments such as GitHub Pages. Manual API key channels remain available. After configuring these deployment variables, the application displays the managed channel named by `OIDC_PROVIDER_NAME`:

```text
OIDC_ISSUER=https://ai.nekotech.us
OIDC_GATEWAY_BASE_URL=https://sub2api.tegical.com
OIDC_CLIENT_ID=oc-example
OIDC_CLIENT_SECRET=...
OIDC_SESSION_KEY=...
OIDC_PROXY_TIMEOUT_MS=600000
OIDC_PROVIDER_NAME=Provider name
PUBLIC_ORIGIN=https://canvas.example.com
```

`OIDC_ISSUER` remains the provider's canonical issuer for discovery, validation, and token exchange. `OIDC_GATEWAY_BASE_URL` is an optional restricted gateway endpoint and defaults to `OIDC_ISSUER` when omitted. To use CDN acceleration, keep `OIDC_ISSUER=https://ai.nekotech.us` and set `OIDC_GATEWAY_BASE_URL=https://sub2api.tegical.com`. Any CDN or reverse proxy in front of it must pass through `Authorization: Bearer`, streaming responses, `Range`, and binary media content, and must not cache authenticated API responses by default. `PUBLIC_ORIGIN` must be the public HTTPS site URL, with the exact callback `{PUBLIC_ORIGIN}/api/oidc/callback` registered at the provider. `OIDC_SESSION_KEY` must be a base64url-encoded 32-byte random key. Set `OIDC_PROXY_TIMEOUT_MS` to `600000` (10 minutes). Users select models from the built-in catalog before connecting, and the BFF requests scopes only for those models; the Sub2API OAuth client's `allowed_llm_scopes` must contain the same model scopes. Changing models requires authorization again.

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The main application container runs the Express OIDC BFF and serves the built Vite application. Canvases, My Assets, generation history, and API keys are stored in the browser by default, while prompt repositories are fetched directly by the frontend. No persistent data volume is required for this data.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
